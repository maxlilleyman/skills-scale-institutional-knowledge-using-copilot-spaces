# OctoAcme Project Management Docs

Welcome to OctoAcme’s project management documentation. These guides provide standardized processes and best practices for managing projects from initiation through retrospective. The docs are organized by lifecycle phase and by audience to make it easy for new teammates and stakeholders to find the guidance they need.

OctoAcme runs projects iteratively with a clear lifecycle — initiation, planning, execution, release, and retrospective — and focuses on delivering small, measurable increments of customer value. Core artifacts include a Project One‑pager / charter, a prioritized backlog and release plan, a Definition of Done, and a living risk register. Ownership is explicit (PM, Product Lead, Developers, QA), and decisions are data-informed to help teams validate outcomes and iterate.

Operational workflows emphasize a board-driven delivery process (Backlog → Ready → In Progress → In Review → QA → Done), small pull requests with linked issues and acceptance criteria, and automated CI checks (tests, linting, security scans) before review. Communication cadence combines short daily standups, weekly delivery syncs, sprint demos, and monthly stakeholder updates to keep progress and blockers visible. Quality is enforced through layered testing: unit tests, integration tests, end-to-end smoke tests for critical flows, CI security scanning, and manual QA as needed. Releases follow a checklist with staging verification and rollback plans, and incidents follow an escalation path (team → PM → Product Lead → Sponsor) with blameless retrospectives to capture action items.
